# 0519. Run Claude in the IDE's terminal rather than a chat of our own

Status: proposed
Date: 2026-09-23

## Context

The sessions feature should let a session be started and continued without
leaving Graphite. Claude Code can be driven in two ways: as its own terminal
program, or headless (`--input-format stream-json`) with the caller drawing
the conversation and answering every permission prompt itself.

## Decision

"New Claude session" opens a tab in `TerminalPanel` running
`claude --session-id <uuid>`, with the id generated by the IDE; "Continue in
terminal" runs `claude --resume <id>`. The session's own tab in the sessions
view follows the transcript Claude writes under that id. `TerminalPanel`
gains `OpenCommand`, which starts a program the way it starts a shell.

## Rationale

The terminal emulator (ADR 0509) already runs full-screen programs at parity
with the system console, so Claude's own interface — permission prompts, slash
commands, modes, skills — works with no code here and keeps working as the CLI
changes. A chat of our own would have to reimplement each of those and chase
every release. Choosing the session id up front is what lets the IDE know
which transcript belongs to the tab before Claude has written anything.

## Consequences

### Positive

- Everything Claude Code can do in a terminal, it can do here.
- The analysis of a running session is the same code as that of a finished one.

### Negative

- The conversation is drawn twice while a session runs: by Claude in the
  terminal and by the sessions view from the transcript.

### Neutral

## Alternatives Considered

- **Headless stream-json with an ImGui chat.** Better integrated to look at,
  but every interactive feature of the CLI becomes ours to rebuild.
